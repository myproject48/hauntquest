## Compatibility review

- The five content JSON files, code-drawn game illustrations, platform launcher
  icons and 20 WAV files have local original source/generators. There are no
  imported stock illustrations, recordings, music packs or model-generated media.
- Resolved Dart packages were checked against their installed license files:
  MIT, BSD-3-Clause and Apache-2.0. These permit distribution alongside MIT project
  code when their notices and applicable terms are retained.
- Flutter SDK source/templates use BSD-3-Clause. The unchanged transparent iOS
  launch images were matched byte-for-byte to the installed Flutter template.
  All launcher icons were regenerated from the original manor painter; no Flutter
  logo is used as the product icon.
- Material Icons use Apache-2.0. The optional Cupertino Icons package is MIT.
  The app uses platform serif fonts; no proprietary font file is bundled.
- Flutter engine components carry their own combined upstream notices, including
  font/Unicode and other component licenses. Those notices are preserved in full
  below and in Flutter's generated binary notice asset. SDK licenses do not change
  the license of HauntQuest's original sources.
- Android platform/plugin dependencies include AndroidX, Kotlin and their
  transitive libraries. Their resolved Maven POM licenses (Apache-2.0 or BSD-3-Clause),
  including inherited parent licenses, were checked; the inventory and original
  JAR/AAR notices are retained in `licenses/`.

This review found no incompatible third-party gameplay asset or source that
requires changing the original project's MIT license. Repeat the review when
adding assets or dependencies. Toolchain executables are not part of the source
release. Flutter and Kiro names are used for attribution, not endorsement.

Regenerate package notices after `flutter pub get`:

```sh
python3 tool/generate_notices.py
```

Reproduce native notice generation after a release build (Java must be on PATH):

```sh
cd android
./gradlew :app:dependencies --configuration releaseRuntimeClasspath --console=plain > ../build/android-dependencies.txt
cd ..
python3 tool/generate_android_notices.py build/android-dependencies.txt --fetch-poms
```

`--fetch-poms` downloads missing license metadata from Google Maven/Maven Central
using TLS-verified `curl`; omit it for a cached offline audit. No executable code
is downloaded. Review unknown licenses rather than bypassing the check.

The three full notice text files are explicitly bundled as Flutter assets in
`docs/licenses/`. Flutter also generates `assets/flutter_assets/NOTICES.Z` inside the APK.
The app exposes these notices through **Credits → Open-source licenses**.
Retain the notices with binary redistribution. The release APK's extracted
notice text is included in the local release artifacts for convenience.

## Original assets

`assets/content/{story,rooms,items,puzzles,choices}.json` and the painters under
`lib/core/painting/` are original project work. Every file under `assets/audio/`
is generated by `tool/generate_audio.py` using oscillators, envelopes and seeded
noise, without sampled recordings. Platform launcher PNG/ICO files are rendered
by `tool/icon/generate_launcher_icon_test.dart`. These original assets use MIT.
No audio service, image CDN, analytics or remote AI dependency is shipped.
