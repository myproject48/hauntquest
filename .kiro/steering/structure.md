## Layer Responsibilities and Rules

| Layer | Contains | May import | Must NOT import |
|-------|----------|-----------|-----------------|
| `domain/` | Game models (`GameState`, `PuzzleProgress`, `StoryFlags`), engine, puzzle evaluators, ending resolver, authored hint provider | `dart:*`, `content/definitions` | `flutter`, `data`, `services`, `features` |
| `content/` | Definition classes, `Condition`/`Effect`, JSON loading and validation | `dart:*`, `domain/models` | `flutter` widgets, `features` |
| `data/` | Save repository, migrator, validator, settings store | `domain`, `content`, persistence package | `features` |
| `services/` | `AudioService`, `AiService` and implementations | interfaces from `domain` | `features`, game rules |
| `app/` | Wiring: `MaterialApp`, routes, `AppScope`, `GameController` | everything below | n/a |
| `features/` | Screens and feature widgets | `app`, `core`, `domain` (read), controllers | other features' internals |
| `core/` | Theme tokens, layout helpers, shared widgets | `flutter` | `domain`, `features` |

## Module Boundaries

- **Game domain models**: immutable, JSON-serializable with primitives only. No UI types.
- **Engine and state management**: the engine is pure and synchronous; the controller owns state, autosave, and the event stream. Widgets dispatch actions, never edit state.
- **Screens and reusable widgets**: screens under `features/<name>/`; anything reused by two or more features moves to `core/widgets/`.
- **Puzzle modules**: one evaluator per puzzle kind in `domain/puzzles/` (pure) and one generic view per kind in `features/puzzles/` (driven by `PuzzleDef.config`). Never hardcode a solution in a widget.
- **Story and narrative content**: JSON in `assets/content/` plus `domain/story/` for choice and ending logic. Narrative text lives in assets, not scattered in widgets (UI chrome strings like button labels may stay in widgets).
- **Assets**: scene art and icons are code-painted (`CustomPainter`). Every file under `assets/` must be listed in `docs/LICENSES_AND_ASSETS.md`.
- **Persistence**: only `data/` talks to storage. Everything else uses the repository interfaces.
- **Optional AI**: only `services/ai/` may perform network calls. Core code depends on the `AiService` interface and the `NullAiService` default. Deleting `services/ai/` implementations must leave the game compiling and fully playable.

## Naming

- Files: `snake_case.dart`. Classes: `UpperCamelCase`. One public primary class per file where practical.
- Feature folders are nouns (`inventory`, `puzzles`). Tests mirror the source path with a `_test.dart` suffix.
- Ids in content are lowercase snake_case strings (for example `entrance_hall`, `silver_cloth`, `p1_mirror_whisper`).
